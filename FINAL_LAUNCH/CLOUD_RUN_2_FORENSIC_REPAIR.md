## Cause 1 — a requested plan that does not exist was an empty success

`nexus-power-grid` and `natkhat-haveli-e4` are not in this repository. They were generated by `plan new` in the
local build that named them and never committed:

```
content/batch_2026-11-20.json
  nexus-node      -> nexus-agents-leave-chat, nexus-small-models, nexus-ai-memory-cost,
                     nexus-data-wall, nexus-on-device
  natkhat-toons   -> natkhat-haveli-e1, natkhat-haveli-e2, natkhat-haveli-e3
```

The consequence was not "plan not found". It was:

```
python -m factory.cli resume   ... --plan-id nexus-power-grid --json   ->  []      exit 0
python -m factory.cli validate ... --plan-id nexus-power-grid --json   ->  []      exit 1
workflow QC step                                                        ->  IndexError: list index out of range
```

`resume` matched nothing, called that "nothing to do", and exited **0**. The workflow's QC step then took
`data[0]` from an empty list and died with an `IndexError` three steps away from the cause. `validate` was only
marginally better: exit 1, message "no rendered artifacts found", still not saying which plan was missing or
what plans do exist.

**Repair.**

- `factory/cli.py::_iter_requested_plans` — one plan walk shared by `resume`, `validate` and `manifest`. A
  `--plan-id` that matches nothing raises `ValueError: plan 'X' is not in this repository; known plans: …`,
  and a channel with no plans for a composition profile is skipped rather than fatal.
- `factory/ops.py::cmd_gate` — the same "no artifact for the requested plan" case now raises instead of
  returning an empty report.
- `.github/workflows/produce.yml` — the QC step checks for an empty report first and prints
  `::error::nothing was rendered for plan 'X' on channel 'Y'; is that plan in content/?`, so a plan problem
  can no longer present itself as an `IndexError`.

## Cause 2 — the gate could not survive a channel with no landscape plan

Run `45071111024` is the interesting one: the Short rendered and **passed QC**, the manifest rebuilt and
verified, and then `Publishing gate` failed with

```
error: ValueError: no long plans for channel 'academic-biohacker'
```

That is my own regression from `b6e76df`. Making the gate iterate both composition profiles was right — it was
the fix for a landscape episode being invisible — but `load_plans_for` raises `ValueError` for a format a
channel has no plans for, and the gate did not catch it. Nexus Node and Academic Biohacker have no
`content/longform/<channel>.json` at all, so **every** shorts gate run on those two channels would have died.

**Repair.** `ops.cmd_gate` catches `ValueError` per profile, records the skipped profile, and prints
`no plans to gate for: <channel>/<format>` in the human output so the coverage gap stays visible. It does not
weaken a check: an episode that does not exist cannot fail a gate.

## Cause 3 — artefacts the manifest hashes were not being uploaded

While verifying the two successful runs I could only check **5 of 8** (short) and **5 of 10** (long) manifest
entries against the downloaded bytes: `timeline.json`, `script.json`, `story.json`, `shot_plan.json` and
`continuity.json` were never uploaded, and `publish_gate.json` was not either. The runner had verified them;
the artefact could not.

**Repair.** Those six paths are now in the `Upload artifacts` list, so "manifest verified" means verified on
the downloaded evidence.
