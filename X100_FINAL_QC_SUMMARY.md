Every number here was read from an artifact, not from a configuration. The first seven episodes were
produced from `main` (`b53a647`/`b496b07`, plus the recovery and delivered-audio fixes in PR #18 where
marked); the three pilot uploads in §8 were produced from `feature/x100-scheduled-publishing` and are the
first artifacts in this project that YouTube has actually accepted. The per-episode tables are generated by
`tools/report_episode_qc.py` into `X100_EPISODE_QC_REPORTS.md`; this file is the mission-level summary of
what those artifacts prove.

## 7. What is not covered by any gate

1. Charts appear only when a sentence states a number, and no topic bank states one — so no real episode
   has drawn a chart.
2. Creative QC does not run for Natkhat or the 16:9 card renderer; both are gated on the 25 technical
   checks alone.
3. Captions are generated but never attached to an upload. This is now **measured**, not suspected: all
   three pilot videos report `contentDetails.caption: false` from the API (§8), and attaching one needs a
   scope the grant does not have.
4. Object-level animation inside a diagram plate does not exist; plates move by camera only.
5. Natkhat wide shots are near-static.
6. A thumbnail can be produced, validated and uploaded correctly and still not appear, because YouTube
   refuses custom thumbnails on a channel that has not completed verification — measured on Academic
   Biohacker with a 403 (§8).

Three Shorts, one per channel, rendered by the code under review and uploaded privately. This is the first
evidence in the project that the gate's verdict survives contact with YouTube.

| Academic Biohacker | `academic-brain-wash` | 25/25 | 25/25 | 38.233 s | 8,170,704 | `O2YiFi0f_Ts` | processed, 1080×1920@30, HD, h264/aac, private, no `publishAt` |
| Natkhat Toons | `natkhat-haveli-e1` | 25/25 | 24/24 | 32.135 s | 4,996,009 | `derJO8hBnjo` | processed, 1080×1920@30, HD, h264/aac, private, no `publishAt`, `madeForKids` true |

What YouTube confirmed, field by field: `uploadStatus: processed`, `processingStatus: succeeded`,
`definition: hd`, one video and one audio stream, `categoryId` 27 / 27 / 1, `defaultLanguage` en / en / hi,
tags present on all three, and the identity check inside each upload result reporting
`token_channel_id == expected_channel_id`.

What it refused: the Academic thumbnail (403, channel not verified for custom thumbnails), and any
post-upload change — `videos.update` returns `403 insufficientPermissions` with the current grant, which is
also why captions cannot be attached and why a scheduled release is one-way.

Deviations worth stating plainly:

- The uploaded file is not byte-identical to the QC'd file from the earlier session run: these three were
  rendered fresh by the code under review, and TTS is not deterministic, so their sha256 differs from the
  episodes in §1. The QC and gate numbers in this table are from the fresh builds.
- The Natkhat gate total is 24, not 25, because the creative check does not run for that engine (§7.2).
